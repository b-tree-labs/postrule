\section{Introduction}\label{introduction}

(Adapted from the prior draft's framing --- keep the ``every production
codebase has classify functions'' motivation, drop product/commercial
language.)

The contribution is \textbf{not} the cascade itself (FrugalGPT-style
cost cascades and learning-to-defer route between models already) and
\textbf{not} the statistical gate (paired McNemar comparison of
classifiers is standard). The contribution is \textbf{the
characterization}: what predicts the right composition, demonstrated
across task families and modalities, plus an algorithm and a learned,
continually-refined policy that operationalize it.

\subsection{Contributions}\label{contributions}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  An \textbf{aligned multi-tier benchmark}: rule / zero-shot LLM /
  few-shot LLM / classical-ML-curve, all scored on one common test set
  per dataset, positioned on a shared labeled-outcomes-consumed axis,
  across 19 text datasets spanning sentiment, intent, moderation,
  emotion, topic, and spam (plus image and audio modalities via the
  rule+ML tiers).
\item
  A \textbf{predictive-characteristics result}: label cardinality
  (Spearman ρ=−0.73 vs outcomes-to-graduate) and rule-over-chance
  predict both transition depth and the cost-optimal terminal tier.
\item
  \textbf{AGA}, an adaptive phase-gate algorithm that chooses the
  terminal tier and graduates under a gate, beating the fixed ladder on
  accuracy \emph{and} labeled-outcome cost.
\item
  A \textbf{non-inferiority (``close-enough'') gate} exposing a single
  cost-tolerance knob, and a continually-refined meta-policy.
\end{enumerate}

\section{Setup}\label{setup}

\begin{itemize}
\tightlist
\item
  \textbf{Tiers / phases.} RULE → MODEL (LLM: zero-shot / few-shot) →
  ML, mapped to the lifecycle phases. The LLM is a neural-net
  decision-maker; ML is a classical sklearn head.
\item
  \textbf{Datasets (19).} banking77, clinc150, hwu64, atis, snips,
  trec6, ag\_news, codelangs, sst2, imdb, rotten\_tomatoes,
  tweet\_eval\{offensive,hate,emotion\}, dair-ai/emotion, dbpedia14,
  yahoo\_answers, 20newsgroups, sms\_spam. Modality generalization
  (image/audio) via CIFAR-10 and ESC-50 on rule+ML.
\item
  \textbf{Aligned protocol.} Common 200-example test subset per dataset;
  rule from a 100-example seed; ML as a curve over training budget; LLM
  (Claude Haiku) zero-shot and few-shot (≤40 exemplars). All tiers
  placed on the labeled-outcomes-consumed axis (rule≈100, zero-shot=0,
  few-shot=k, ML=budget).
\end{itemize}

\section{Adaptive Graduated Autonomy}\label{adaptive-graduated-autonomy}

\begin{itemize}
\tightlist
\item
  \textbf{oracle\_terminal} (cost-aware): highest-accuracy tier; among
  those within ε, prefer cheapest to operate. The LLM wins only when
  strictly \textgreater ε better.
\item
  \textbf{Tie-to-graduate} and \textbf{crossover}: ML graduates once it
  \emph{ties} (non-inferiority) the LLM, not once it beats it ---
  because trained ML is far cheaper per call.
\item
  \textbf{CostToleranceGate}: the non-inferiority gate; the ε knob is
  operator-tunable.
\item
  \textbf{AGAMetaPolicy}: predicts the terminal tier from
  early-observable characteristics; continually refined as new streams
  append rows.
\end{itemize}

\section{Limitations (honest)}\label{limitations-honest}

\begin{itemize}
\tightlist
\item
  Early-only terminal prediction is weak (0.32 oracle-match); the
  budget-aware policy is stronger (0.62). Oracle noisy at n=200 ---
  larger-n re-run planned.
\item
  MODEL tier is text-only so far; audio/video MODEL requires a
  multimodal LLM (the gate is modality-agnostic; only the LLM input
  differs).
\item
  Single LLM (Haiku); single classical head family.
\end{itemize}

\section{Related work}\label{related-work}

FrugalGPT / LLM cascades (cost routing); learning-to-defer (per-example
deferral); champion-challenger + shadow deployment (MLOps); McNemar /
Dietterich (classifier comparison). AGA differs: a \emph{learned,
continually-refined, cross-stream} policy that predicts the right
composition from data-stream characteristics and chooses the terminal
tier, rather than routing per example or hand-tuning a cascade.
